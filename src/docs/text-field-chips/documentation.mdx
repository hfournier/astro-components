## Attributes

Every attribute except `class` and `maxlength` goes on the `<input>`: `name`, `required`, `disabled`, `placeholder`, `autocomplete`, `aria-*` and the rest, as on [TextField](/components/text-field). `name` is the chips' to submit under, not the text's. `class` goes on the element around the whole field, so it can place and size it.

## Chips

Fill the `chips` slot with [ChipInput](/components/chip-input)s for the field's starting chips, as M3's Guidelines page shows for the contacts in an email's "To" field, or the terms in a search field. The chips sit inline with the cursor, in a [ChipGroup](/components/chip-group) named by the field's label, and wrap onto new rows or, with `overflow="scroll"`, scroll sideways in one row (ADR-0026). A field can start with no chips.

- **Adding:** Enter turns the typed text into an editable chip, before the cursor. First the input fires an `add` event, which bubbles and is cancelable, with `detail.value` (the text, which the chip submits) and `detail.label` (what it shows). Call `preventDefault()` to refuse the text, which stays in the field, such as an address that isn't a contact; set `aria-invalid="true"` and swap in error text to say why. Set `detail.label` to show something else, such as the contact's name for their address. Enter on an empty field submits its form, as a text field's does.
- **Removing:** Backspace with the cursor at the start of the text selects the chip before it, and a second Backspace deletes it, as M3's Guidelines page describes. Typing instead goes on in the text, and the chip is deselected. Each chip's remove button, and Backspace or Delete on a chip, remove it too, and fire ChipInput's `remove` event. On a page in another language, name the remove buttons and edit fields of the chips the field makes with `removeLabel` and `editLabel`, and those of the `chips` slot's own chips with ChipInput's props of the same names.
- **Editing:** a tap on an editable chip turns it back into the text it stands for: its value, such as a contact's address, not the name it shows. Enter commits the edit, and the new text becomes the chip's label and value, as typed text does. To edit a contact as M3's Guidelines page shows, as `Name <address>`, write that text on ChipInput's `edit` event and split it back into the name and the address on its `change` event, as in the example below.
- **Moving:** drag a chip to another place in the field, or into another field of the same form, such as from "To" to "Cc". From the keyboard, Shift with ArrowLeft or ArrowRight moves the focused chip a place, and Shift with ArrowUp or ArrowDown moves it to the end of the previous or next field.
- **Submitting:** each chip submits its value under the field's `name`: its `value` attribute, such as a contact's address, or else its label, in the chips' order, whether or not it's selected. The typed text, not yet a chip, doesn't. A `required` field is satisfied by one chip.
- **Overflow:** a scrolling field behaves as text does, as M3 asks: unfocused, it shows the start of its content, and focusing it puts the cursor at the end of the text, scrolled into view.

A filled field with a label is 64px tall for a row of chips, the floated label above them; outlined or unlabelled, it's 56px. The label floats while the field holds a chip, and the field shows its focus indicator while a chip in it is focused. Otherwise its states, colors and motion are TextField's.

```astro
<form>
  <TextFieldChips name="to" type="email" class="w-full" id="to">
    To

    <Fragment slot="chips">
      <ChipInput value="ziad@example.com" isEditable>Ziad Aouad</ChipInput>
    </Fragment>
  </TextFieldChips>
</form>
<script>
  type Detail = { value: string; label: string };
  type EditDetail = Detail & { text: string };
  const contacts: Record<string, string> = { "ping@example.com": "Ping Qiang" };
  const to = document.getElementById("to");

  // Typed text: refuse what isn't an address, and show a known contact by name
  to?.addEventListener("add", (event) => {
    const detail = (event as CustomEvent<Detail>).detail;
    if (!detail.value.includes("@")) event.preventDefault();
    else detail.label = contacts[detail.value] ?? detail.value;
  });

  // Editing a contact: open it as "Name <address>"…
  to?.addEventListener("edit", (event) => {
    const detail = (event as CustomEvent<EditDetail>).detail;
    if (detail.label !== detail.value)
      detail.text = `${detail.label} <${detail.value}>`;
  });

  // …and read the name and the address back. A bare address may be a contact's.
  to?.addEventListener("change", (event) => {
    const detail = (event as CustomEvent<Detail>).detail;
    const [, name, address] = detail.value.match(/^(.+?)\s*<(.+)>$/) ?? [];
    if (address) [detail.label, detail.value] = [name, address];
    else detail.label = contacts[detail.value] ?? detail.value;
    if (!detail.value.includes("@")) event.preventDefault();
  });
</script>
```

The `edit` event's `detail` has the chip's `label` and `value`, and the `text` the edit opens with, its value by default. The `change` event's `detail.value` and `detail.label` both start as the committed text; whatever you set them to, the chip shows and submits. Call `preventDefault()` on `edit` to keep a chip from opening, or on `change` to refuse the text and keep the edit open.

## Motion

Chips that change place slide on M3's fast spatial spring; their colors change on fast effects, as ChipInput's do. The field's own motion is TextField's. Under reduced motion, everything changes at once.
