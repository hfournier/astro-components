## Style by emphasis

Pick the style by how important the action is:

- **Filled:** the final, most important action in a flow, such as Save, Join now or Confirm. Ideally there's one per page.
- **Tonal:** a lower-priority action that needs a little more weight than an outline, such as Next in an onboarding flow.
- **Elevated:** only when the button needs to stand out from a busy or patterned background.
- **Outlined:** important actions that aren't the primary one, often next to a filled button, on simple backgrounds.
- **Text:** the lowest-priority actions, in cards, dialogs and snackbars. Don't underline it: for something that looks like a link, use a link.

Don't use too many buttons. Move low-priority actions into an overflow menu, or use icon buttons (ButtonIcon) for them.

## Labels

- Keep labels to 1–3 words, in sentence case: "Save draft", not "SAVE DRAFT" or "Save Draft".
- The accessible name should match the visible label, so speech-control users can say what they see. It can add context after it, such as `aria-label="Delete, Draft 3"`, but should start with the label.

## Width

A button is as wide as its label, never narrower: its label doesn't wrap or truncate. With `showFullwidth`, cap the button's width on large windows, such as with `class="max-w-sm"`, so it doesn't become a long, flat bar.

## Toggle buttons

Use a toggle for a binary action that the button turns on and off, such as Save or Favorite. With an icon, use an outlined icon while it's unselected and the filled one while it's selected: give `icon` the outlined name, such as `"favorite"`, and the toggle switches to `"favorite-fill"` on its own (see ButtonIcon's docs for icons without a filled version). If the label changes with the state, keep both labels about the same length, so the button doesn't jump in width. To react to a change, listen for the button's `click` event and read the new state from `aria-pressed`.

## Opening a menu

A Button opens a Menu with `command="toggle-popover"` and `commandfor` set to the menu's `id`. The menu gives it `aria-haspopup="menu"` and `aria-expanded`, and while the menu is open the button keeps its pressed state layer, as M3 asks.
