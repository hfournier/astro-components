## Plain or rich

- **Plain:** a label for an element that has no visible text, such as an icon button. An element with a text label doesn't need one.
- **Rich:** a longer explanation or definition, with an optional subhead and actions.

Don't hide critical information in a tooltip, where it's easy to miss. Use a Dialog instead.

## Writing

- **Plain tooltips:** keep the text brief, ideally one line. Describe the action, not the icon: "Share", not "Arrow".
- **Rich tooltips:** keep the subhead to one line that sums up the message. Use at most two short text Buttons as actions, side by side rather than stacked.

## Placement

A **plain** tooltip goes inside the element it labels, and the element must be positioned (e.g. `relative`). M3 puts it 4px above an element with a visible boundary, such as a button. Next to plain text, leave 8px instead by passing `class="mb-2"`. In an app bar, place it below with `placement="below"` (and `class="mt-2"` next to text). ButtonIcon already includes one, so you only need a plain Tooltip for other elements.

A **rich** tooltip can hold buttons, which can't go inside another button or link, so it goes right after the element it describes, with that element's `id` as `for`. It's centered below its element, which M3 allows on desktop. It stays open while the pointer or focus is on either the element or the tooltip, so the pointer can move onto its actions. Keyboard users reach the actions with Tab.

## Showing and hiding

As in M3:

- **Opening:** a tooltip shows 500ms into a hover, or straight away on keyboard focus. On a touchscreen it shows on a long press. The click that ends a long press is ignored, so holding an icon button to read its label doesn't also press it.
- **Closing:** a tooltip stays for 1.5 seconds after the pointer leaves or the finger lifts. Moving keyboard focus away hides it straight away.
- **One at a time:** showing a tooltip hides any other straight away. The exceptions are a rich tooltip that holds keyboard focus, and a persistent one, which stay.

A **persistent** rich tooltip (`isPersistent`) works differently. A click on its element opens it, and it stays open until the person interacts with something else: a click anywhere else, focus moving elsewhere, Escape, or another click on the element. Don't use one on an icon button, since the icon button's click is its action. To introduce a new feature, a page can open one as soon as it loads with `showPopover()`. Give the Tooltip an `id`, then call `document.getElementById("whats-new").showPopover()`. A tooltip that opens on its own should always have a `subhead`, so it's clear what it's about.

## Accessibility

A plain tooltip is hidden from assistive tech, so its text should repeat its element's accessible name, such as an icon button's `label`. It deliberately has no `tooltip` role: screen readers would otherwise read the name twice.

A rich tooltip has the `tooltip` role, as M3 asks, and its subhead and text become its element's accessible description (`aria-describedby`); the actions aren't included. That departs from the ARIA Authoring Practices, whose tooltips never hold anything focusable: M3's rich tooltip can have actions, and the description still reaches screen readers through `aria-describedby`, while keyboard users reach the actions with Tab. Both variants can be dismissed with Escape, and stay open while the pointer is over them, as WCAG 1.4.13 requires.
