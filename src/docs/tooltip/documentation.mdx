## Placement

A **plain** tooltip goes inside the element it labels, and the element must be positioned (e.g. `relative`). It shows after a short delay while the element is hovered, and straight away while it has keyboard focus. ButtonIcon already includes one, so you only need a plain Tooltip for other elements.

A **rich** tooltip can hold buttons, which can't go inside another button or link, so it goes right after the element it describes, with that element's `id` as `for`. It opens on hover and keyboard focus, and stays open while the pointer or focus is on either the element or the tooltip, so the pointer can move onto its actions. Keyboard users reach the actions with Tab.

## Accessibility

A plain tooltip is hidden from assistive tech, so its text should repeat its element's accessible name, such as an icon button's `label`. Don't put information only in a plain tooltip.

A rich tooltip's subhead and text become its element's accessible description (`aria-describedby`); the actions aren't included. Both variants can be dismissed with Escape, and stay open while the pointer is over them, as WCAG 1.4.13 requires. Tooltips don't open on touchscreens, so don't rely on them for anything a touch user needs.
