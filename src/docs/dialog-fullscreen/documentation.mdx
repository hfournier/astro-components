## When to use it

Use a full-screen dialog for a task that needs the whole screen of a phone:

- a task with several steps, such as creating a calendar event with its title, date, location and time
- content that needs keyboard input, such as form fields
- changes that aren't saved straight away
- a task that opens other dialogs. Only a full-screen dialog can have another dialog over it.

M3 keeps full-screen dialogs to compact windows, such as phones. From a medium window up, DialogFullscreen is a basic dialog, like Dialog. It changes in CSS alone, so if the window is resized while it's open, its content, form values and focus stay where they are.

## Actions

The actions move with the dialog, as in M3:

- **Compact windows:** a close icon button at the start of the header, its only navigation, and the confirming action at the end. The `actions` slot is a bottom action bar.
- **Medium windows and up:** no close icon. The `actions` slot, then the dismissing action (`closeLabel`) and the confirming action sit at the end of the action row, as in DialogConfirm.

Each of these is rendered in both places, and the one that doesn't apply is hidden with `display: none`. So at every width there's one close or dismiss button and one confirm button, reached with Tab in the order they're shown, and both copies behave the same.

Name the confirming action after what it does, such as "Save", "Send" or "Create", not "Done", "OK" or "Close", and never disable it. When it succeeds, don't open another dialog; open one only if it fails.

## Unsaved changes

If closing would lose changes, ask first, with a DialogConfirm such as "Discard draft?". The page knows whether there are changes, so this is up to you, but DialogFullscreen lets it happen: the close button, the dismissing action, Escape and a click on the scrim (from medium up) all fire a cancelable `cancel` event first. Prevent it to keep the dialog open, and open the DialogConfirm instead.

## Errors

Show a field's error inline, next to the field. Show a general error, such as a failed network request on save, in a basic dialog (DialogAcknowledge).

## Accessibility

DialogFullscreen keeps the native `dialog` role, not `alertdialog`, since it holds forms and other content. When it opens, focus goes to its first interactive element: the close button in a compact window, and the first field (or the dismissing action) from medium up. Focus stays inside it while it's open, and returns to the button that opened it when it closes.
