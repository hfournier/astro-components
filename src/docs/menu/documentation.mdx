## Triggers

Any button opens the menu with `command="toggle-popover"` and `commandfor` set to the menu's `id`, such as a Button, a ButtonIcon or a plain `<button>`. Menu's script finds its triggers, and gives each `aria-haspopup="menu"`, `aria-controls` and `aria-expanded`, kept in step with the menu. A Button or ButtonIcon keeps its pressed state layer while its menu is open, as M3 asks. A menu can have more than one trigger; it opens beside whichever opened it.

## Placement

The menu is in the top layer, in front of everything else. It opens below its trigger, lined up with the trigger's start edge (its right edge, right to left), 4px away. When there isn't room below, it opens above, and when there isn't room at that edge, it lines up with the other one. The menu keeps 48px from the window's top and bottom. When it's taller than the room on either side of its trigger, it takes the roomier side and scrolls, in the standard layout, since M3 has no gaps in a scrolling menu. It fits again as the page scrolls or the window resizes while it's open. Its scrollbar follows the user's system setting, so on macOS it may only show while scrolling.

## Appearance

The menu is 112px to 280px wide, as wide as its widest item, at elevation 2. In the grouped layout, each MenuGroup is a surface with M3's group corners: 16px at the menu's outer corners, 8px between groups. In the standard layout, the menu is one surface with 16px corners, and a divider, inset 12px, separates its groups. A menu without MenuGroups is one surface in either layout.

The menu opens and closes with a short fade, or none with reduced motion.

## Choosing an item

The page handles each item's `click` as usual. Choosing a MenuItem closes the menu once the click's handlers have run, and returns focus to the trigger, unless a handler has moved focus elsewhere, such as into a dialog it opened. A MenuItemCheckbox toggles and the menu stays open, as M3's multi-select menus do. A MenuItemRadio checks itself, unchecks the other radio items in its group, and closes the menu. Both fire a `change` event on the menu, whose `detail` is the item's `{ name, value, checked }`:

```js
document.querySelector("#format-menu").addEventListener("change", (event) => {
  const { name, value, checked } = event.detail;
});
```
