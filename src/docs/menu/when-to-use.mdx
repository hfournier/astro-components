Use a menu for a temporary set of actions or choices, opened from a button, an icon button or another control, such as an overflow menu behind a "More options" button, or a choice of sort order. A menu takes less room than a row of radio buttons or chips. For actions that should always be visible, use buttons or a toolbar instead.

- **Groups:** a gap (the grouped layout) or a divider (the standard layout) bundles similar items. Keep a grouped menu to one or two groups, and use the standard layout for a menu tall enough to scroll. A grouped menu that has to scroll takes the standard layout, as M3 has no gaps in a scrolling menu.
- **Colors:** vibrant menus stand out more; use them sparingly.
- **Items:** keep labels short. Disable an item that's unavailable rather than removing it, so the menu keeps its shape. Icons are decorative, so the label must say it all.
- **One thing per item:** don't put buttons, switches or other controls in an item.
- **Submenus:** use them to organize a complex set of options on larger screens, where there's room beside the menu. Keep the tree shallow, one level where you can.
- **Context menus:** use one for actions on a specific element, such as an image or a row. Right-click is hard to discover, so never make it the only way to an action.

### When not to use it

- In a compact window, consider a SheetBottom instead, which has room for more items and longer labels.
- For navigation between a site's main destinations, use a NavBar, NavRail or Tabs.
- For a FAB's related actions, use a FabMenu.
