# Structural & typographic tokens: radius, border-width, font-weight, font-size, focus-ring

> **Superseded in part by the move to Material 3**: the border-width decision below is withdrawn. M3 draws every outline and divider these components use at 1px (outlined buttons, cards, dividers), so there's no scale left to name: components use Tailwind's plain `border` utility, and the `--theme-border-width-*` tokens are gone. Border colors come from M3's `outline-variant` role (and `outline` where M3 calls for a stronger boundary) rather than a separate border token. The radius decision is withdrawn as well: M3 fixes its corner sizes (extra-small 4px, small 8px, medium 12px, large 16px, extra-large 28px) rather than scaling them from one dial, and the `--radius-sm`-`-xl` steps the dial produced only repeated Tailwind's defaults, so `--radius`, its scale and its `--radius-*` role tokens are gone. Components use Tailwind's `rounded-*` classes where one matches the M3 size (`rounded-xl` for 12px, `rounded-2xl` for 16px, `rounded-full` for a pill), and an arbitrary value where none does (`rounded-[28px]` for Dialog's extra-large corners, `rounded-[14px]` for the medium square Button and TabList's matching focus outline). A literal is acceptable here because the value is M3's, fixed by the spec, not a project-wide dial anyone is expected to turn. The font-weight decision is withdrawn too: every component now takes its weight from an M3 type style, so all the font-weight roles (`control`/`title`/`nav`, and the heading roles ADR-0008 kept) are gone. Of the decisions below, only the focus-ring one still stands - a dedicated token rather than a component's own color - now as `--theme-color-focus-ring-on-bg`, which BaseWrapper sets per background. Only the color half of it survives: the `--focus-ring-width`/`--focus-ring-offset` pair is gone, and components write the ring's geometry as Tailwind utilities (`focus-visible:ring-3 focus-visible:ring-offset-2`, offset filled with `--theme-color-wrapper-bg` so it matches the surface behind it). A 3px ring with a 2px offset is still one fixed pair project-wide, just not a token; the font-size portion was already replaced by ADR-0008. The tokens now live in `src/styles/theme.css`, not `global.css`.

Radius, border-width, and font-weight were hardcoded per component with no shared scale (Dialog/Popover escalate radius across breakpoints, Button doesn't; Button/DialogConfirm use `font-medium`, TabList uses `font-semibold`; Tab's focus ring has no color token at all). This decision defines the token scale for all four, following the mechanism ADR-0004 already settled (native `@theme` namespaces for radius/font-weight, hand-rolled custom properties for border-width), and folds in a font-size scale surfaced while designing font-weight's heading roles.

- **Radius**: one base token `--radius` (0.5rem) drives `--radius-sm/-md/-lg/-xl` via `calc()` multipliers, mirroring how color derives from `--color-primary`. Dialog/Popover's breakpoint escalation (`rounded-xl → md:rounded-2xl → lg:rounded-3xl`) is dropped in favor of one flat value at every screen width — a second axis (viewport) riding on the same dial as "how rounded" conflated two independent decisions nothing asked for. `rounded-full` (Popover's circular close button) stays outside the scale; it's a shape, not a scale point.
- **Border-width**: hand-rolled literal steps, `--border-width-thin` (1px) and `--border-width-md` (2px) — no base-token/`calc()` treatment, unlike radius. Border-width isn't a natural single dial (Tailwind's own utilities are fixed 0/1/2/4/8 with no configurable scale); nobody asks to sweep it from thin to thick globally. Which step a component uses follows a **boundary vs. divider** rule: boundary (md) is a border that IS the load-bearing visible shape of a control (Button's outline, each TabList tab's reserved frame); divider (thin) merely separates two already-grouped regions (Dialog's header/footer rule, Popover's close-button edge, and — applying the rule consistently — TabList's own container rule, which drops from 2px to 1px).
- **Font-weight / font-size**: alias Tailwind's native `--font-weight-*` (medium/semibold/bold) and `--text-*` namespaces directly rather than overriding their values — both already have sensible defaults matching what's in use today.
- **Role-token layer**: every one of the four properties gets a second, role-named alias on top of its raw value token (`--radius-control: var(--radius-sm)`, not `--radius-sm` used directly) — see `CONTEXT.md`'s **Role token**. The raw names (`sm`/`md`/`xl`, `medium`/`semibold`) describe magnitude, not when to reach for them; the role name does. This is the same naming instinct color's `primary`/`secondary`/`grayish` roles already embody, extended to properties where Tailwind's own vocabulary doesn't carry intent.
- **Component title vs. document heading**: DialogConfirm's `<h3>` is a **component title** (see `CONTEXT.md`), not the third level of a page heading hierarchy — it gets its own role (`--font-weight-title`/`--font-size-title`), independent of the (currently unused) **document heading** scale. This resolves a monotonicity problem: folding the `<h3>` into a shared h1–h6 scale would have made it lighter than h4–h6, the wrong direction.
- **Font-size gets three fluid roles**: `--font-size-title`, `--font-size-heading-sm`, `--font-size-heading-lg` hold `clamp()` expressions instead of aliasing a static `--text-*` step — headings and titles read better scaling continuously with viewport than jumping at breakpoints. `--font-size-control`/`--font-size-nav` (Button, TabList) stay static: button and tab labels shouldn't resize with viewport the way prose does.
- **Focus-ring**: `--color-focus-ring` is a dedicated token (defaults to `var(--color-primary-control)`, see ADR-0007), not a direct reference to a component's own color-role prop — so a consumer picking `color="secondary"` on one component doesn't silently change what focus looks like project-wide. `--focus-ring-width`/`--focus-ring-offset` (2px/2px) are one fixed pair project-wide, not sized per component — a focus ring is a system-level accessibility affordance, not a visual-weight decision.

This is spec-only: it adds the tokens to `global.css`'s `@theme` block and documents the intended per-component mapping, including for components with no matching consumer yet (document headings, and every focus-ring consumer besides `Tab`). It does not edit `Button.astro`/`Dialog.astro`/`Popover.astro`/`TabList.astro`/`Tab.astro` to actually reference these tokens — that retrofit is deliberate follow-on work, out of scope on the map (issue #1).

This is hard to reverse once components are retrofitted against it, surprising without knowing why a second role-named layer sits on top of Tailwind's own scale (or why one heading-tagged element is deliberately excluded from the heading scale), and reflects real trade-offs: a role-alias layer over direct Tailwind classes, `calc()`-derived vs. independent radius steps, and fluid `clamp()` vs. static breakpoint-stepped font sizes.

## Consequences

Two visual changes ship the day components are retrofitted onto these tokens, even though this ticket doesn't make them: Dialog/Popover's radius stops growing across breakpoints (settles at the old `xl` value everywhere), and TabList's container rule thins from 2px to 1px.
