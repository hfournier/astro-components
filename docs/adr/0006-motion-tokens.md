# Motion tokens: duration & easing scale

Duration and easing were hardcoded per component with no shared scale: `BaseOverlay` hardcodes `duration-300 ease-out` for its dialog and separately for its backdrop; `Button`/`TabList` ride Tailwind's implicit 150ms default with no explicit easing; `Tab` hardcodes `duration-300`/`duration-500` across its transition variants. This decision defines the token scale for both, following the mechanism ADR-0004 already settled and the base-token/role-token pattern ADR-0005 used for radius/border-width/font-weight.

- **Duration mechanism**: hand-rolled literal steps, not a base-token `calc()`-derived scale. Tailwind v4 has no `--duration-*` namespace (only a fixed `--default-transition-duration: 150ms`), the same non-namespace situation ADR-0004 already put border-width in — and like border-width, duration isn't a natural single dial: nobody asks to sweep every transition faster or slower as one move. The one case where every duration genuinely needs to move in lockstep — reduced motion — is handled separately below, not by this scale. Three steps, matching every value already hardcoded across components so no visual change ships: `--duration-fast` (150ms), `--duration-base` (300ms), `--duration-slow` (500ms).
- **Duration role layer**: a role-named layer on top, same as radius/border-width/font-weight got (see `CONTEXT.md`'s **Role token**): `--duration-feedback` (Button/TabList hover-color feedback, → fast), `--duration-overlay` (BaseOverlay's dialog and backdrop transitions, TabList's indicator slide, → base), `--duration-content-swap` (Tab's panel-swap transitions, → slow).
- **Easing**: Tailwind v4's native `--ease-in`/`-out`/`-in-out` namespace already extends cleanly, exactly as ADR-0004 promised for namespaced token types — no custom curve is added, since nothing currently hardcodes anything beyond `ease-out` (`BaseOverlay`) or the browser's implicit default (everything else). One role token, `--ease-overlay`, aliasing `--ease-out` for `BaseOverlay`'s open/close pattern; every other component stays on the implicit default until one actually diverges.
- **Reduced-motion interaction**: no token-level duplication. `motion-safe:` keeps gating the whole `transition-*`/`duration-*`/`ease-*` utility trio as a presence/absence toggle, exactly as ADR-0003 already mandates — this decision doesn't introduce a new mechanism, it confirms the existing one is sufficient. When `motion-safe:` withholds the utilities, the property change collapses to a single CSS step with no transition, which is indistinguishable from "still happens, just instant" for an essential transition and from "skipped outright" for a decorative one. Neither case needs a separate `--duration-instant` or a `prefers-reduced-motion`-scoped redefinition of the scale: there's nothing left for the token layer to do once the utility itself is gated.

This is hard to reverse once components are retrofitted against it, surprising without knowing Tailwind v4 tokenizes easing but not duration, and reflects a real trade-off: literal independent steps (border-width's treatment) vs. a `calc()`-derived scale (radius's), decided against the latter for lack of any dial-shaped use case.

## Consequences

Spec-only, same as ADR-0005: this adds the tokens to `global.css`'s `@theme` block and documents the intended per-component mapping. It does not edit `BaseOverlay.astro`/`Button.astro`/`TabList.astro`/`Tab.astro` to reference them — that retrofit, including fixing `BaseOverlay`'s dialog/backdrop transitions currently missing `motion-safe:` entirely (already flagged in ADR-0003), is deliberate follow-on work, out of scope on the map (issue #1). No visual change ships from this ticket alone.
