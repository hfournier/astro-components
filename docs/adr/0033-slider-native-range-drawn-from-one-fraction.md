# A slider is a native range input its script moves, drawn in CSS from one fraction

M3 Expressive's standard slider (#207) draws a track split around the handle by a 6px gap, with 2px corners beside the handle and M3's corner size at the ends. A track shorter than its corner isn't drawn. It has stop indicators in two colors, one for each track, an inset icon that moves to the inactive track when the active one is too short to hold it, five sizes, a vertical orientation and a right-to-left one. A native `<input type="range">` styled with its `::-webkit-slider-thumb` and `::-moz-range-thumb` can draw none of the split track, and it maps the pointer to a value in its own way in each browser, orientation and direction. We decided:

1. **The input stays the control, hidden over the slider and taking no pointer events.** It carries the name, role, value, `aria-orientation`, form value, reset and validation, and keyboard focus. Everything visible is drawn beside it.
2. **The script sets the value from the pointer and the keys itself.** A press anywhere on the slider focuses the input, without a focus ring, and sets the value under the pointer, as dragging does. With stops, it snaps to the nearest stop as drawn. Keys follow M3's table: arrows, Page Up and Page Down, an arrow with Space held, Home and End. Left and right follow the track's direction. Each change fires `input`, and `change` once it's set, as a native slider's would. The browser snaps a value to `step` when it's set.
3. **CSS draws every part from two custom properties the script sets on the slider:** `--ac-slider-fraction`, how far along the range the value is, and `--ac-slider-inset`, 1 when the handle sits on a stop between the ends. Compose places those stops inset from the ends. The track is a size container, so `100cqi` is its length. Each part's place and length is `calc()` from those three. A step that's 0 below a threshold and the length above it, such as a track that isn't drawn when shorter than its corner, is `max(0px, min(L, (L - corner) * 100000))`. The server renders the starting fraction, so the slider is drawn before the script runs.
4. **Each stop and the inset icon is drawn in both tracks, which clip them.** A stop shows in whichever track holds it, in that track's color, and a stop under the handle's gap shows in neither. This avoids working out in a script which stops are active.
5. **Vertical is a vertical writing mode, from the bottom up** (`writing-mode: vertical-lr; direction: rtl`). Every part is placed with logical properties (`inset-inline-start`, `inline-size`, `border-start-start-radius`), so one set of rules draws both orientations and right to left. The value indicator's text turns back to horizontal.

We rejected restyling the native thumb and track. They can't draw a split track or two colors of stop, and the stops would need their own positions anyway. We also rejected letting the hidden input take the pointer. Each browser maps it with its own thumb width, so the drawn handle and the value would drift apart, and Compose's inset stop positions couldn't be matched.

## Consequences

- The slider doesn't move without its script. Its starting value is drawn, but neither pointer nor keys change it until the script runs.
- A page that sets the input's `value` from a script dispatches an `input` event so the slider redraws. A form's reset, and a value the browser restores when going back, are redrawn by the script itself.
- The centered and range sliders (#208) can reuse this model: more fractions, and more tracks clipping the same stops.
